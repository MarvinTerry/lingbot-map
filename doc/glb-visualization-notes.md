# GLB 可视化与第一人称飞行方案

## 1. 当前事实核实

当前仓库导出的 `GLB` 本质上是离散着色点云，不是重建后的连续网格。

- 在 [`lingbot_map/vis/glb_export.py`](../lingbot_map/vis/glb_export.py) 的 `predictions_to_glb()` 里，`world_points` 会被拉平成 `vertices_3d`，颜色来自输入图像，再通过 `trimesh.PointCloud(vertices=..., colors=...)` 写入场景。
- 这意味着导出的主体是 `PointCloud`，视觉上会天然带有空洞、离散点、近景穿透感强的问题。
- 当前 viewer 里的 `GLB` 导出还有两种风格：
  - `Points`：直接导出点云，速度快，文件更轻。
  - `Spheres`：把每个点替换成一个小球，画面更饱满，但文件体积和导出成本会明显上升。

结论：你之前判断“模型输出更像离散着色点云”是对的。

## 2. 为什么第一人称画面不一定好看

点云适合全局浏览，不天然适合沉浸式第一人称飞行。

- 点与点之间没有真正表面，镜头贴近时容易看到空隙。
- 遮挡关系不稳定，尤其是前景稀疏时会显得“漏风”。
- 远看通常还可以，近距离穿越建筑、树木、栏杆时会明显暴露离散采样痕迹。
- `GLB` 只是容器，不会自动把点云变成电影感镜头。

## 3. 仓库里已经有的能力

当前代码已经具备做“第一人称可视化原型”的基础，不需要从零实现。

- [`lingbot_map/vis/point_cloud_viewer.py`](../lingbot_map/vis/point_cloud_viewer.py) 里有 `_move_to_camera()`，可以把 viewer 相机切到重建相机附近。
- 同文件里有 `save_video()`，可以从当前 viewer 视角逐帧渲染并编码成 `mp4`。
- 同文件里导出 `GLB` 时还能附带相机和轨迹，这对离线渲染很有帮助。

结论：最短路径不是先研究更复杂的渲染器，而是先把“相机路径 + viewer 录制”这条链打磨好。

## 4. 可选方案

### 方案 A：基于现有 viewer 的第一人称录制

做法：

- 让 viewer 相机沿重建相机轨迹运动。
- 在相机前方加少量平滑和前视偏移，避免镜头抖动和“贴脸穿点”。
- 用现有 `save_video()` 输出第一人称 `mp4`。

优点：

- 开发量最小。
- 可以直接复用现在的 `viser` 交互和导出链路。
- 适合尽快做出“能看”的服务端版本。

缺点：

- 画质上限受点云本体限制。
- 录制依赖 viewer 渲染视角，不是严格意义上的离线电影级渲染。

建议：

- 这是最值得先做的版本。

### 方案 B：导出 `GLB + camera_path.json`，交给 Blender 离线渲染

做法：

- 继续导出点云 `GLB`。
- 同时导出一份相机路径、FOV、时间轴信息。
- 在 Blender 中导入点云和相机，做轨迹平滑、景深、运动模糊、色彩调节，再离线出片。

优点：

- 画面控制力强。
- 很适合做宣传视频、演示素材、固定镜头成片。

缺点：

- 工程链更长。
- Blender 对超大点云的实时体验不一定好，需要做抽样、半径控制或转成更友好的表示。

建议：

- 这是“效果优先”的中期方案。

### 方案 C：把点云升级成 surfel / splat 风格渲染

做法：

- 不再把输出仅视为裸点云，而是转成带半径、法线、透明度的 surfel，或者进一步转成类似 Gaussian Splatting 的表示。
- 使用自定义渲染管线输出第一人称动画。

优点：

- 画质潜力最高。
- 最接近“飞行穿越很好看”的目标。

缺点：

- 开发复杂度高。
- 需要额外的几何/渲染研究，不适合作为服务端第一阶段。

建议：

- 这是长期路线，不建议作为当前仓库的第一优先级。

## 5. 我的推荐顺序

建议按下面顺序做：

1. 先把 viewer 第一人称录制做成稳定功能。
2. 再补 `GLB + camera_path.json` 的离线渲染接口。
3. 之后再决定是否投入自定义 splat/surfel 渲染。

## 6. 面向服务端的落地建议

如果未来要在服务端自动产出“第一人称飞行视频”，最务实的路线是：

- 推理完成后产出 `predictions`。
- 生成点云场景和相机轨迹。
- 对相机轨迹做平滑、限速、轻微前视偏移。
- 输出 `scene.glb`。
- 输出 `flythrough.mp4`。

这样用户既能拿到原始三维结果，也能拿到便于传播的可视化视频。
