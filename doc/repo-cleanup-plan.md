# 仓库整理方案

## 1. 当前问题

当前仓库根目录同时混着源码、模型权重、推理产物和临时文件，开发体验会越来越差。

目前已经能看到几类容易把根目录弄乱的内容：

- 本地模型权重：`checkpoints/`
- 推理输入或中间产物：根目录 `*.mp4`、`*_frames/`
- 推理输出：根目录 `*.glb`
- 正式源码和包：`lingbot_map/`
- 未来准备新增的服务端代码：`lingbot_map_server/`

## 2. 本次整理的原则

- 不做大规模移动，避免破坏你当前已经可运行的路径。
- 先建立规范，再逐步迁移。
- 让根目录尽量只保留“源码、配置、文档、示例”。

## 3. 建议的目标结构

建议逐步收敛到下面这个结构：

```text
lingbot-map/
├── doc/
├── lingbot_map/
├── lingbot_map_server/
├── example/
├── assets/
├── checkpoints/
├── outputs/
├── README.md
├── pyproject.toml
└── uv.lock
```

各目录职责建议如下：

- `doc/`：放架构说明、设计讨论、渲染方案、服务端路线图。
- `lingbot_map/`：保持为模型、推理、可视化的核心库代码。
- `lingbot_map_server/`：放 API、任务编排、存储、渲染服务逻辑。
- `checkpoints/`：本地模型权重，仅开发机使用，不纳入 Git。
- `outputs/`：放所有生成物，例如上传缓存、抽帧目录、推理结果、`glb`、第一人称视频、调试截图。

## 4. 这次已经做的低风险整理

本次只做了两类低风险动作：

- 新增 `doc/`，把 GLB 可视化和后续服务端方案固定下来。
- 更新 `.gitignore`，忽略本地权重和根目录生成物，减少 Git 噪音。

特意没有做的事情：

- 没有直接搬动你根目录现有的 `mp4`、`glb`、抽帧目录。
- 没有重命名已有 Python 包路径。
- 没有提前创建复杂的服务端骨架。

这样做是为了不打断你现在已经能跑通的推理链。

## 5. 下一阶段建议

等你开始做 `lingbot_map_server/` 时，建议顺手完成下面几件事：

1. 让服务端所有输入输出默认写入 `outputs/`。
2. 把“上传文件”和“渲染产物”按 job id 分目录保存。
3. 把 viewer 录屏、GLB、日志都放到统一 job 目录。
4. 仅保留 `example/` 里的静态示例素材，其余实验产物不再放根目录。

## 6. 关于 `uv.lock`

既然你已经明确使用 `uv` 管理环境，`uv.lock` 建议保留并纳入版本管理。

原因很简单：

- 它能帮助服务端部署复现依赖组合。
- 后续涉及 `flashinfer`、`viser`、`trimesh`、`onnxruntime` 这类版本兼容时，锁文件会很有价值。
